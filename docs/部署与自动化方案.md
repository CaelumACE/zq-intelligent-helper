# 部署与自动化方案（Cloudflare + GitHub Actions）

> 更新时间：2026-08-27
> 目标：研发提交 Git 后，自动构建前端部署到 Cloudflare Pages，VM 上 Docker 跑后端 + cpolar 隧道提供公网 API。

## 一、结论先行

| 部分 | 方案 | 是否需要域名 |
|---|---|---|
| 前端（静态） | Cloudflare Pages + GitHub Actions 自动部署 | 不需要，给 `*.pages.dev` |
| 后端（FastAPI + SSE） | 一台服务器跑 Docker + cloudflared | 不需要，给 `*.trycloudflare.com`，正式建议固定域名 |
| 数据库 | PostgreSQL + pgvector（Docker 内） | 不需要 |

Cloudflare 本身免费、自动 HTTPS、全球 CDN，是无域名阶段最优解。

## 二、当前自动化已落地

新增 `.github/workflows/`：

1. `ci.yml`
   - 后端：安装依赖 + 校验 FastAPI app 可正常导入（保证路由/代码无语法错误）。
   - 前端：`npm ci` + `npm run build`，产出 `frontend/dist` 静态文件并上传 artifact。

2. `deploy-cloudflare.yml`
   - 在 CI 成功后触发（`workflow_run`）。
   - 用 `cloudflare/wrangler-action@v3` 把 `frontend/dist` 部署到 Cloudflare Pages，项目名 `zq-intelligent-helper`。

### 需要浩哥做一次的一键配置（约 3 分钟）
1. Cloudflare 控制台创建 Pages 项目 `zq-intelligent-helper`。
2. 生成 API Token（`Account.Firewall rules` / `Cloudflare Pages` 编辑权限）。
3. 在 GitHub 仓库 `Settings → Secrets and variables → Actions` 添加两个 secret：
   - `CF_API_TOKEN`：上一步的 Token
   - `CF_ACCOUNT_ID`：Cloudflare 账户 ID
4. 之后每次 `git push origin main`，都会自动构建并发布到 `https://zq-intelligent-helper.pages.dev`。

## 三、后端如何自动化

后端是运行态服务，Cloudflare Pages 是纯静态托管，无法直接跑 FastAPI。方案的取舍：

### 推荐：独立服务器 + Docker
- 服务器跑 `docker compose up -d`（已包含 FastAPI + postgres/pgvector + nginx）。
- 用 `cloudflared tunnel --url http://127.0.0.1:80` 打公网。
- 正式环境在 Cloudflare Zero Trust 建命名隧道，绑定固定子域名。
- 自动化方式：`deploy-cloudflare.yml` 里增加 SSH 到服务器执行 `git pull && docker compose up -d --build`。

### 备选：纯前端先行（本阶段可用）
- 前端部署到 Cloudflare Pages 后，前端先展示 UI/交互。
- 后端等服务器确定后，再把 `/api` 从本地指向真实后端地址。
- 前端 API 地址用 `VITE_API_BASE` 环境变量统一配置。

## 四、前端环境变量改造点

建议在 `frontend/vite.config.ts` 引入 `VITE_API_BASE`，默认 `/api`：

```ts
server: {
  proxy: { '/api': process.env.VITE_API_BASE || 'http://localhost:8000' }
}
```

生产环境 `VITE_API_BASE=https://某固定域名`，即可让 Cloudflare Pages 上的前端直连后端。

## 六、VM 标准更新流程（2026-08-27 定稿）

> 适用：研发代码合入 main 后，在 VM（`/home/wzh/gov-assistant`）上更新部署。
> 背景：M2 端口隔离后 backend 只 `expose: 8000`（不映射宿主机），统一由 nginx 80 端口入口；cpolar 隧道转发 80。

### 标准命令（一键执行）
```bash
cd /home/wzh/gov-assistant && \
git fetch origin && \
git reset --hard origin/main && \
docker compose build && \
docker compose up -d && \
sed -i 's/addr: 8000/addr: 80/' ~/.cpolar/cpolar.yml && \
pkill -f cpolar; sleep 2; \
nohup cpolar start-all --config /home/wzh/.cpolar/cpolar.yml > /home/wzh/cpolar.log 2>&1 & disown && \
sleep 5 && \
docker compose ps && \
curl -s http://127.0.0.1/health && \
echo "" && \
grep -o 'https://[a-z0-9]*\.[a-z0-9]*\.cpolar\.[a-z]*' /home/wzh/cpolar.log | head -1
```

### 验收标准
- `docker compose ps`：backend / frontend / postgres 三容器全 `Up`。
- `curl http://127.0.0.1/health` 返回 `{"status":"ok",...}`。
- 末行 grep 输出当前 cpolar 公网 URL。

### 关键注意事项
1. **必须 `docker compose up -d`，不能用 `restart`**：`restart` 不重读 `.env`，改了环境变量不生效。
2. **不加 `--no-cache`**：Docker 自动缓存未变的层，加速构建；仅改 `requirements.txt`/`package.json` 时才需考虑。
3. **health 检查走 80 端口**：M2 后 8000 不映射宿主机，`curl 127.0.0.1:8000` 必然失败；nginx 已配 `location /health` 反代。
4. **cpolar 配置用绝对路径**：`--config /home/wzh/.cpolar/cpolar.yml`，不要用 `sudo`（sudo 下 `~` 解析为 `/root` 找不到配置）；参数是 `--config` 不是 `-c`。
5. **cpolar 免费版 URL 每次重启可能变化**：若末行输出的 URL 与当前不一致，通知小赵更新 `.github/workflows/deploy-cloudflare.yml` 的 `VITE_API_BASE` 并重新部署。
6. **health 失败排查**：`docker compose logs --tail=50 backend`。
