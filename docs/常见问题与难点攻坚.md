> 目的：把研发过程中真实踩过的坑、攻克的难题和解决方案沉淀下来，持续更新，用于复盘、面试准备和后续迭代。

## 一、当前技术栈

- 前端：React + TypeScript + Vite + Tailwind CSS
- 后端：FastAPI + httpx（异步）
- 大模型：MiniMax（主）、DeepSeek（兜底，双通道可切换）
- Embedding：MiniMax `embo-01`（1536 维）
- RAG：意图识别 + 关键词/语义混合召回 + LLM 生成 + 引用溯源
- 存储：Day1 用 JSON 文件 + 内存；Day2+ 升级 PostgreSQL 16 + pgvector
- 部署：Docker Compose + nginx（已备），最终公网部署待服务器/域名

## 二、踩坑与解决方案

### 1. Python 3.13 下 `jieba` 无法使用
- **现象**：`jieba` 分词组件的兼容层引用 `pkgutil.ImpImporter`，Python 3.13 已移除该 API，导入/运行报错。
- **处理**：本轮不硬改库，改用轻量中文 n-gram 匹配 + 语义向量召回，后续分词场景再评估其他方案。
- **经验**：做中文分词/检索前，先确认运行环境 Python 版本与分词库兼容性。

### 2. MiniMax Embedding 参数报错 `2013 missing required parameter`
- **现象**：调用 `/embeddings` 接口只传模型和文本时报参数缺失。
- **根因**：MiniMax Embedding 要求显式传 `type` 字段，`query`（查询侧）与 `db`（文档侧）两种类型。
- **解决**：查询时用 `type=query`，入库时用 `type=db`；向量维度为 1536。
- **经验**：接新模型 API 时先看官方参数表，优先最小可用请求定位报错字段。

### 3. 检索“问公文种类却生成通知模板”
- **现象**：问“公文有几种类型”，系统却套用“通知”模板生成公文。
- **根因**：纯关键词/词面匹配把“公文”误配到“通知模板”，没有区分“知识问答”与“公文写作”意图。
- **解决**：
  - 新增三种意图分类：知识问答 / 公文写作 / 办事指引，路由到不同 prompt。
  - 补充 16 条《党政机关公文处理工作条例》文种知识库。
  - 检索纳入完整字段（文号、材料、步骤、类别、文种）与同义词扩展。
- **经验**：RAG 的质量上限由“理解意图 + 检索质量 + prompt 约束”共同决定，不能只调检索。

### 4. LLM 失败后降级到 mock 假数据
- **现象**：前端/演示出现“当前为静态演示版本”的写死文案，用户体验是“系统在骗人”。
- **根因**：早期左路兼顾 mock 演示；超时/失败时错误降级到静态文案。
- **解决**：去掉假 mock 降级，取消知识库命中直接“超范围拒答”；双通道都失败时只罗列知识库原文并明确提示，不编造。
- **经验**：生产/验收场景宁可“明确拒答”，也不能回退到虚假内容；错误要打日志、可追踪。

### 5. 长回答 10~17 秒，不满足 TTFT ≤ 5s
- **现象**：MiniMax 非流式生成长公文时总耗时 10~23.5s，用户干等。
- **根因**：非流式请求要等模型全部生成完才返回，首字也一起延迟。
- **解决（进行中/已落地第一版）**：
  - 后端新增 `POST /api/chat/stream` 的 SSE 接口。
  - 前端用 `fetch + ReadableStream` 解析 `meta / delta / done` 事件，边生成边上屏。
  - 双模型实测：MiniMax 平均 TTFT ~575ms，DeepSeek ~533ms；总耗时 DeepSeek ~2.8s 明显优于 MiniMax ~12.9s。
- **经验**：响应速度问题优先看“首 token 时间（TTFT）”和“总耗时”两个指标，SSE 流式是性价比最高的优化。

### 6. SSE 流式实现中 `async for` 报错 coroutine
- **现象**：`async for delta in self.chat(...)` 报 `'async for' requires an object with __aiter__ method, got coroutine`。
- **根因**：`chat()` 定义成 `async def`，流式分支 `return self._stream_response(...)` 返回的是协程，需要先 `await` 拿到 async generator 再遍历。
- **解决**：改为 `async for delta in await self.chat(messages, stream=True, provider=...)`。
- **经验**：`async def` 返回值一定是 awaitable，即使是 async generator 也要先 `await` 得到对象。

### 7. `.env` 路径加载错误
- **现象**：后端读不到环境变量，MiniMax Key 为空。
- **根因**：`load_dotenv` 的相对路径受工作目录影响，导致 `.env` 未被加载。
- **解决**：基于 `__file__` 计算项目根目录的 `.env` 绝对路径后再加载。
- **经验**：后端启动入口路径不固定时，配置文件不要依赖相对路径或进程 cwd。

### 8. Git 推送冲突 / TLS 中断
- **现象**：多人协同推送到 `main` 时出现远程有新提交冲突，以及 `GnuTLS recv error`。
- **处理**：冲突用 `git pull --rebase` 解决；网络抖动稍后重试，代码未丢失。
- **规范**：每个人推送前先 `git pull`；关键版本打 tag；危险密钥不进仓库、加入 `.gitignore`。

## 三、架构决策记录（简版）

| 决策项 | 结论 | 原因 |
|---|---|---|
| SQLite vs PostgreSQL | 最终用 PostgreSQL 16 + pgvector，Day1 先用文件/内存 | 并发、合规审计、向量检索需求 |
| 关键词检索 vs 向量检索 | Day1 关键词/混合召回，Day2 转 Embedding + Rerank | 先保演示，再提语义质量 |
| 单模型 vs 双通道 | MiniMax 主通道 + DeepSeek 兜底，可用数据选主次 | 稳定性与成本/延迟对比 |
| 非流式 vs SSE | 统一改 SSE 流式 | 降低体感等待，满足 TTFT |

## 四、面试可展开的知识点

- 为什么要用 RAG，而不是直接微调模型？
- 向量检索和关键词检索的本质区别，什么场景需要混合召回？
- `pgvector` 的向量索引类型（IVFFlat / HNSW）与近似最近邻搜索。
- SSE 与 WebSocket 的区别，为什么聊天场景常用 SSE？
- Python 异步生成器与协程的关系（`async for` + `await`）。
- 大模型 API 的双通道兜底与可观测性（TTFT、总耗时、引用准确率、幻觉率、拒答率）。
